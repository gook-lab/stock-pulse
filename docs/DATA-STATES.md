# 외부 데이터 상태 처리

StockPulse는 여러 외부 API의 응답을 한 화면에서 사용합니다. 화면은 값뿐 아니라 출처, 갱신 시점, 연결 상태를 함께 표시해야 합니다.

## 화면 상태

| 상태 | 의미 | 화면 처리 |
|---|---|---|
| live | 현재 외부 API에서 받은 값 | 출처와 갱신 시점을 표시 |
| stale | 새 요청은 실패했지만 이전 정상값이 있음 | 마지막 값과 갱신 지연을 함께 표시 |
| mock | 개발용 대체 데이터 | 실제 데이터와 구분되는 배지 표시 |
| empty | 정상 응답이지만 값이 없음 | `-` 또는 빈 상태 안내 표시 |
| error | 사용할 현재값과 이전값이 모두 없음 | 오류 안내와 재시도 동작 제공 |

대체 데이터는 실제 데이터처럼 표시하지 않습니다. `source`, `stale`, `generatedAt`, `configured` 같은 메타데이터를 컴포넌트까지 전달해 사용자가 현재 상태를 판단할 수 있게 합니다.

## KIS 요청 제한

모든 KIS 요청은 서버의 공용 요청 큐를 통과합니다. 5xx 또는 429 응답이 발생하면 요청 간격을 늘리고, 성공이 이어지면 간격을 서서히 줄입니다.

주문 요청은 공용 계층에서 자동 재시도하지 않습니다. 전송 결과를 확인하지 못한 상태에서 같은 주문을 다시 보내면 중복 주문이 발생할 수 있기 때문입니다.

## 캐시와 부분 실패

서버 캐시는 새 요청이 성공하면 값을 교체합니다. 요청이 실패하고 이전 값이 있으면 해당 값을 `stale: true`와 함께 반환합니다. 화면은 데이터를 유지하되 갱신이 지연됐다는 사실을 숨기지 않습니다.

여러 데이터 소스 중 일부만 실패한 경우 전체 화면을 오류로 바꾸지 않습니다. 실패한 영역만 이전 값, 빈 상태 또는 오류 상태로 전환합니다.

## 실시간 연결

브라우저는 KIS WebSocket에 직접 연결하지 않고 백엔드의 SSE 엔드포인트를 구독합니다. 백엔드는 KIS 연결 하나를 유지하며 체결과 호가를 여러 브라우저에 전달합니다.

종목을 변경할 때에는 이전 종목의 값을 즉시 제거합니다. 늦게 도착한 이전 응답이 현재 종목의 데이터처럼 보이지 않도록 요청과 응답의 대상을 대조합니다.

## 검증

```bash
pnpm test
pnpm validate
```

테스트에서는 목 데이터가 실데이터 영역으로 새지 않는지, 이전 값에 `stale` 표시가 붙는지, 빈 배열과 네트워크 오류가 서로 다른 화면 상태로 이어지는지 확인합니다.
